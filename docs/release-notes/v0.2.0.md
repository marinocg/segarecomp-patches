# segarecomp Patches v0.2.0: Castle of Illusion widescreen + Practice+

One individually installable `.segapatch` package for **Castle of Illusion Starring Mickey Mouse** (Sega Genesis / Mega Drive). It works only with the exact original image below. No game data is included; supply your own legally obtained image.

| Package | Version | Schema | Trust | Exact original image SHA-256 |
|---|---|---|---|---|
| `castle-of-illusion-widescreen-practice` (Castle of Illusion Starring Mickey Mouse, USA/Europe, 524,288 bytes) | 0.1.0 | 3 (native ABI 2) | trusted native source | `2d535ff7eda650a64a9093ba6fabf8d5ac87801b898a76b591db41a1c8e47c4f` |

The package SHA-256 is in `SHA256SUMS` and in the catalog. The collection version `v0.2.0` is unrelated to the package version. This release contains **only** this package: the Castle activation variants, the debug free-fly mode and the input recorder are not part of it.

## What it does

* **Widescreen at 16:9, 21:9 and 32:9.** The game's own picture stays 320 pixels wide and untouched; the package supplies the scenery beside it. Authored scenery (rebuilt from the game's own work-RAM maps) covers the **17 verified scrolling scenes**; menus, cutscenes, level loads and any other layout use the host's generic extension. At Original and 4:3 only the native picture is shown.
* **The picture is placed inside the widened view**: at the left at a level's first column, centred in the middle of the level and at the right at its last column, over a long ramp.
* **Actors beside the picture.** Sprites the game would clip at the screen edge are drawn in the extra columns using the game's own art, priority and palettes (presentation only).
* **Practice+** (optional, player-invoked): pressing A+B+C together while a verified level runs restores Mickey's power to full, exactly as the game's own refresh routine would leave its state. The chord is taken away from the game while a level runs. Lives and everything else are never touched. There is no on-screen indicator.

## Is gameplay modified?

No, with one exception: **Practice+** changes Mickey's power only when you invoke it. The widescreen scenery and actors are presentation only and never write to the game. The package declares exactly three guest-memory write ranges (the power word, the five HUD slot words and one HUD flag byte), used only by Practice+.

## Read before installing

* This is **executable C11 source** that is compiled into the Patched program. It is **not sandboxed**, and a SHA-256 is an integrity check, not publisher authentication. You approve the exact package identity when you install it; install only what you trust. The package declares the capabilities `frame.work_ram`, `hook.function`, `host.log`, `input.intercept`, `input.read`, `memory.read.m68k.work_ram`, `memory.write.m68k.work_ram`, `scenery.words` and `state.mod`.
* **Compatibility: a segarecomp build from the product's `main` after v0.8.0 is required.** The package needs schema 3 / native ABI 2 support and the SDK features of product ADRs 0311 to 0315. **No tagged segarecomp release (v0.8.0 and earlier) can install it.** The package is built with product revision `8d419ab`. See [docs/installation.md](https://github.com/marinocg/segarecomp-patches/blob/main/docs/installation.md).
* A different image, region or revision is refused by digest. A title or file name is never an identity.

## Known limitations

* **Coverage is the verified scenes only** (17 scrolling scenes). Boss rooms and rooms the verification did not enter were not individually examined. Other layouts fall back to the host's generic extension.
* **Evidence tier: synthetic-only in this repository.** Automated tests run on fabricated data; the real-image checks were done locally by the maintainers and are described, in aggregate, in the package README. CI never uses a commercial image.
* **Parallax while the picture slides.** The game draws its background layers for its own camera, and the package can only place the finished picture. While the picture is being repositioned inside the widened view (the ramps near a level's start and end, up to about six view margins of camera travel), the layers are offset from the view's world and move slightly slower than the game's own scrolling: measured on the first stage, about 2 of every 12 pixels of camera travel inside those zones. Elsewhere the picture is centred and layers move at the game's own speeds.
* The status bar, drawn by the game on the VDP window plane, is not relocated.
* Actors the game itself never creates (it activates layout objects only a limited distance ahead of the camera) are not invented.
