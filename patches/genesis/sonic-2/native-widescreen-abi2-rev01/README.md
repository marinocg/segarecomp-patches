# Sonic the Hedgehog 2 (Genesis, JUE REV01): native widescreen as a schema 3 / ABI 2 package (SEG-152-T010)

> The ABI 2 successor of the [Sonic 2 widescreen provider](../native-widescreen/README.md) for **JUE REV01** only: the same game knowledge, constants and verification logic, the same BPS delta and the same scope (reconstructed scenery of the single-player running levels and attract demos, the relocated animated HUD), delivered through the exact-frame ABI 2 API (scenery windows, the per-row generic mask, one RGBA bitmap, refusal with the ABI 1 reason). The ABI 1 package of this revision stays published and unchanged.

**Status: candidate (not approved for release selection).** It is not released: no release selects it, so it has no catalog entry and no release asset. Its package version `0.1.0` is recorded in [`package.json`](package.json) (identity and SHA-256 from the product's `mod pack` at the revision pinned in `scripts/PRODUCT_REF`).

## What is carried over, what changes

Unchanged from ABI 1: the work-RAM map, the per-zone background wrap rules, the identity check against the VDP (tolerances, edge bands, at most 32 own-plane lines per plane), the scope (Emerald Hill, Metropolis, Hill Top, Oil Ocean, Mystic Cave, Casino Night, Chemical Plant, Death Egg, Aquatic Ruin, Wing Fortress, Sky Chase; split-screen, special stages and bonus stages are declined), the HUD pieces and the label-frame rule.

Changed (only how the answers are delivered): the ABI 1 per-cell callback becomes up to two scenery windows per plane built from the frame's own copies (a cell asked by two lines that need different words would make the frame unservable and is refused honestly, never answered half-way; none occurred, see the evidence); the lines the ABI 1 provider answered from the VDP's own plane (the last two lines, and lines the identity check found unlike the layout) become the per-row generic mask; the HUD overlay becomes one 104 x 216 RGBA bitmap with the same fallback position; a declined frame is a *refusal* with the ABI 1 diagnostic reason.

## Cross-frame state (ADR 0320 decision 3)

The ABI 1 provider kept two values across frames, both written at presentation time: `g_prev_level` (the HUD is accepted only when the previous produced frame was also a level frame) and `g_hud_frame` (the label frame the game last really built, shown unchanged during the level-restart fade after a death). **Classification: both are essential state, not caches.** Clearing `g_prev_level` before every presented frame declines the HUD on every frame, and clearing the label state changes the HUD picture (demonstrated at the level start, where the RINGS label flashes between its palettes); the hold of the label through the level-restart fade is covered only as far as the recorded run and the attract demos reach a HUD-only frame (see the evidence). They are therefore maintained in the `frame-end` phase (which runs for every guest frame whether or not it is presented) in a four-entry record ring keyed by guest frame number, serialized through `state.mod` (schema 1, 64 bytes), and read at `render` for the guest frame whose end-of-frame RAM is the view's copy. After save/load, rewind and any skipped presentation the provider accepts exactly the frames an uninterrupted run accepts; no frame is conservatively declined by the provider (the host's own `STALE_STATE` for the first newly produced frame after a restore applies to ABI 1 and ABI 2 alike).

## Evidence (local, aggregate only)

* **Input, and why it is a recording.** The gameplay scenes are driven by ONE recorded input session (6,202 guest frames: title, menus, then Emerald Hill Zone 1 played with running, jumping and ring collection) that is replayed frame-exactly in the ABI 1 and the ABI 2 program through the viewer's session seam. A host-poll-keyed pad script was tried first and is NOT used: it lands a frame or two differently in the two build routes, the guests then diverge (guest RAM differed by thousands of bytes even against the unpatched-provider build) and nothing could be compared. A first set of runs was also done with a pad that left the game paused: those results are discarded and replaced by the runs below. The viewer verifies a replay against the recording only for the program that recorded it (ABI 1: its checkpoints pass; ABI 2: reported `complete_unverified`), so ABI 2 equality is established by this comparison itself, not by that check.
* **Per-frame equality, five presentation modes (32:9, 21:9, 16:9, Original, exact 4:3), the recorded gameplay each:** 6,203 produced frames per mode, 31,015 in total; ABI 2 equals ABI 1 in every mechanism (every ordered verdict occurrence: status, side, placement, accepted components, reason, authored; coverage accounting offered/accepted/presented/rejected for scenery and HUD; the final picture byte for byte; the final guest work RAM): **0 differences**. Scenery was served on 5,029 frames in every mode except Original (which asks for none: 0 in both ABIs) and the HUD on 5,029, identically for both ABIs. Every run is also validated as evidence (exit status, terminal outcome, consecutive frame progression to the scripted end, coverage and capture present).
* **Attract-mode demos (title left idle, no input), 32:9 and 16:9:** 28,010 produced frames, 9,840 scenery frames, 0 differences; the demo checkpoints below reach Aquatic Ruin, Casino Night, Chemical Plant (act 1 each).
* **Aspect transitions inside the recorded run (32:9 -> 21:9 -> 16:9 -> Original -> exact 4:3 -> 32:9):** 6,203 frames, 0 differences; the replay of the same run reproduces every verdict and the final picture for both ABIs.
* **Save/load and rewind through the real viewer** (the level left alone after the menus, so no input edge can land differently in the two build routes; a quick save, a quick load into a later position, a visual rewind with repeated frame numbers): for each ABI every trace occurrence after the restore equals the uninterrupted run's verdict for its frame number except the single newly produced frame after the restore, which the host reports as `STALE_STATE` for ABI 1 and ABI 2 alike (load: 2,702 occurrences, 1 forward discontinuity; rewind: 2,702 occurrences, 10 repeated frame numbers). The ABI 2 occurrences, pictures and RAM equal the ABI 1 run's occurrence by occurrence, so no frame an uninterrupted run presents is conservatively declined after a restore.
* **Visual checkpoints, pixel for pixel:** 19 intermediate frames, each the final capture of an ABI 1 and an ABI 2 run of the same input ending on the SAME guest frame (checked), 19 with **0 differing pixels** (geometry equal, 960 x 672). Classes: gameplay with visible off-screen scenery at 32:9, 21:9, 16:9, Original and exact 4:3 (guest frame 3,502); the HUD eight frames later; the level start with no rings (the RINGS label in both palettes, frames 1,302 and 1,310); a HUD-only frame inside the level run (frame 2,889, two frames after the first frame in which only the HUD was served: Sonic hurt) and one in the attract demos; three attract-demo frames in other zones with other parallax layouts; a generic scene the provider declines (the SEGA logo, frame 7); the aspect-transition run at 16:9, Original and back at 32:9; one post-load and one post-rewind frame. Liveness is checked (two checkpoints eight frames apart differ in picture and RAM, so the guest is not paused).
* **Inspected by eye** (the images are local): I looked at ABI 2 captures of these JUE REV01 scenes: Emerald Hill Zone 1 at guest frame 3,502 in 32:9 and 16:9 (terrain slopes, palms, log bridge and parallax sea continue in both margins, no blank or repeated margin, no seam, HUD anchored at the left edge of the extended view, unclipped); the level start with no rings at frame 1,302 (RINGS label red, the world's left edge shows the background hills and flowers beside the level); and the Chemical Plant (frame 4,970) and Aquatic Ruin (frame 8,182) demo frames (continuous extended scenery, distinct parallax layouts). Each is identical to its ABI 1 capture (0 differing pixels); the REV01 frames also look the same as REV00's at the same guest frames. No unexplained artifact was seen. Not looked at by eye (compared numerically only): the other REV01 checkpoints.
* **Falsification (each variant of the real ABI 2 source must FAIL the same comparison):** a wrong frame lag fails on accepted-components, coverage-accounting, ordered-occurrences; `g_prev_level` cleared before every presented frame fails on accepted-components, coverage-accounting, ordered-occurrences, picture, reason; the label state cleared fails, at the rings-zero frame, on picture; the maintained state dropped on restore changes the occurrences after a load; an injected range fault (an oversized bitmap layer) fails on accepted-components, authored, coverage-accounting, ordered-occurrences, picture, reason.
* **Injected fault:** exactly 1 `E_MOD_FAULT cause=range` disables the provider; the presented frame and the guest RAM equal those of the BPS-patched image with no provider at all (picture equal: True, RAM equal: True); the fault never touches the guest.
* **Cost (class level):** one exact-frame `render` and one `frame-end` per produced frame. A 6,203-frame run takes 95.5 s with the ABI 2 package against 93.3 s with the ABI 1 package (+2.2 s, about +0.35 ms per frame; whole-viewer wall clock measured while other comparison runs shared the machine, so class-level only and well inside the 16.7 ms frame budget). Copies: the host's exact-frame view is 188,416 bytes per frame (SEG-152-T008); the provider adds one 104 x 216 RGBA bitmap (89,856 bytes) and at most four windows of 4,096 words.
* **Scenery gate (SEG-152-T001/T007):** no frame of any compared scene asked one plane cell with two different answers (a conflicting frame would be refused and show as an accepted-component difference); the own-plane lines of the ABI 1 provider are expressed with the T007 per-row generic mask with identical `authored` accounting. The class that blocks Sonic 1 (SEG-152-T009, see its README) did not occur in these scenes.
* **Not exercisable on the real image, stated rather than assumed:** split-screen (two-player), special-stage and bonus-stage frames, frames at a width other than 320 px, and a player death with the level-restart fade (the HUD-only frames reached are one hurt-Sonic frame of the recorded run and one attract-demo frame). Their declines are the verbatim ABI 1 gates ported unchanged. Zones other than the ones named above were not visited.

Reproduce with `tools/abi_parity_compare.py` (needs the legally held image and a product checkout; it prints counts and pass/fail classes only and writes nothing commercial anywhere). Public CI cannot run it and does not depend on it; the repository checks (`check_repo.py`, the catalog check, the unit tests, a deterministic rebuild of the package with the pinned product CLI) are what CI runs.
